# Thyme-Me: context for coding assistants

Thyme-Me is a source-available Windows desktop time tracker with approved product, interface, and technical baselines and an active modular implementation. `docs/product/SDD.md` is the product authority, `docs/engineering/TECHNICAL_DESIGN.md` is the implementation-method authority, `docs/engineering/IMPLEMENTATION_PROMPT.md` is the execution scope, and `docs/engineering/CODE_MAP.md` plus `docs/engineering/feature-index.json` map features to governing code. Do not invent behavior for decisions marked open.

Core product:
- Local-first and offline-capable; students are primary, but work/research/personal use is supported.
- Home screen resembles a DAW mixer: one vertical strip per top-level Stream.
- A Stream can be a course, job, client, research area, hobby, or similar context.
- A scoped Category belongs to exactly one Stream; a global Category has no Stream parent.
- A Project is standalone or optionally owned by one Stream.
- A Session can be stray or use at most one Stream, multiple Categories, and one Project. Scoped Categories and an owned Project must match the Stream; a global Category does not require one.

Timing and capture:
- Start timing in an in-app dialog. Bare duration means minutes; `h` means hours.
- Bounded Sessions stop automatically; all Sessions preserve timestamps/date/time-zone context.
- Continue creates a new independent Session from a historical Session and does not copy timestamps or description.
- Common manual entries can be recreated quickly as new Sessions.
- Completion dialog appears after tracked/manual time. `Enter` saves/exits, even empty; `Shift+Enter` adds a line break.
- Exactly one Session runs globally and every started Session requires a duration. Pause/resume is supported. Pre-start Cancel creates no record; after start, Stop always saves elapsed time.
- Pomodoro repeats to a chosen total duration, remembers adjusted work/break defaults, uses a five-minute work buffer before break confirmation, and manually confirms every next work interval.

History and Stats:
- Built-in history filters by Stream, Category, Project, duration, date, billability, and origin; sorts by date, duration, and relevant names.
- Stats contains a local day/hour timeline plus weekly/monthly totals and charts by Stream, Project, Category, and billability.
- Stats defaults to a four-month Daily heatmap and raw actual time, with an explicit Effective/Rounded basis. It includes five headline metrics, Daily/Weekly/Cumulative/Timeline views, Stream/Project rankings, additive breakdowns, and no productivity targets. Timeline geometry always uses raw timestamps.

Billing, rounding, archive, and data:
- Billability and wage are optional; preserve historical rate/status.
- Rounding is off by default, configurable globally/per Session, and never destroys raw timestamps/duration.
- Streams, Categories, and Projects are archivable/restorable without changing history.
- CSV and JSON export semantics are defined; physical column/property ordering is frozen during technical design without changing those semantics.
- Offline local-file backup/restore is required; never include credentials silently.
- Optional time budgets belong to Streams/Projects, use raw actual time, are non-recurring by default with optional weekly/monthly reset, and have no alerts. Billing uses rounded effective time.

Windows lifecycle:
- Active Session + close: hide to notification area and continue. Nothing active/pending + close: exit.
- `Ctrl+W` and `Alt+F4` invoke that state-dependent close behavior; `Ctrl+Q` is explicit quit. Only documented contextual navigation, search, zoom, accessibility, layout, close, and quit shortcuts are allowed.
- Optional idle/display handling stops on detected display-off/lock/screen-saver/suspend and notifies on next activity.
- When enabled, active, and foreground, Thyme-Me requests prevention of automatic sleep/display-off. Never block explicit user sleep/lock/shutdown.
- Windows wake prevention does not itself prevent screen savers; framework-specific handling must be tested.

Optional integrations and privacy:
- Google Calendar does not ship initially. Preserve an integration boundary for a possible later backend-free read-only overlay and event-to-manual-Session conversion; the local timeline never depends on it.
- Foreground-app tracking is off by default, opt-in, only active during Sessions, local, visible, and deletable.
- Baseline foreground data is application identity and duration only. No keystrokes, screenshots, clipboard/content, browser history, window titles, or domains.
- Never request administrator access for initial foreground-application tracking. Inaccessible elevated intervals are retained as Unknown elevated application.

Appearance:
- Modes: Light, Dark, Follow Windows, or scheduled switching.
- Default is GitHub-inspired Light/Dark.
- Each variant uses three primary palette colors: Canvas, Surface, Accent; supporting colors are derived/system-defined.
- Preset order: GitHub Default, Codex Plus, Catppuccin, Gruvbox Medium, Solarized, Claude-inspired Warm, Google-inspired Material, Nord-inspired, Dracula-inspired, Monokai-inspired.
- Custom palettes accept light/dark `#RRGGBB` triplets, import/export, contrast preview, and accessibility warnings.
- Exact preset hex values and derivation await visual design. Custom colors are text hex in Settings; saved presets are JSON. Low contrast warns but is allowed after acknowledgement; custom palettes are an explicit contrast-conformance exception while built-in/default palettes target WCAG 2.2 AA.

Guardrails:
- Use timestamps, not UI ticks, as time truth.
- Preserve raw and rounded values separately.
- Keep optional features progressive and core tracking simple.
- Do not add cloud sync, accounts, telemetry, teams, approvals, GPS, screenshots, targets, or extra shortcuts.
- Keep data in per-user Windows app data and secrets in protected credential storage.
- Keep README.md, `docs/product/SDD.md`, `docs/engineering/TECHNICAL_DESIGN.md`, `docs/product/CONTEXT.md`, and this file synchronized.
- Treat all strings, files, archives, JSON/CSV, URIs, update metadata, and future integration payloads as untrusted. Parameterize SQL and structured process calls; never interpolate input into SQL, shells, scripts, markup, paths, format strings, or unbounded regexes.
- Defend imports/exports against spreadsheet-formula injection, ZIP traversal/decompression bombs, malformed or oversized JSON, overflow, invalid relationships, excessive nesting/counts, and unbounded allocation. JSON/backups retain exact original text; reversible CSV neutralization is documented.
- Commit timing transitions before showing success. Recover after app/process/Windows/PC crash or power loss from the last committed state, detect unclean shutdown, validate integrity, and never replace a corrupt store silently.
- Bound and stream/page/virtualize/cancel collections, caches, queues, reports, imports, exports, backups, and network responses. A true process-wide memory exhaustion terminates for next-launch recovery rather than continuing unsafely.
- Add hostile-input, disk-full, corruption, forced-termination, power-loss, scale, bounded-memory, and deterministic-cleanup tests with the affected subsystem.

Repository workflow:
- Thyme-Me is a one-person project. Commit directly to `main` by default rather than creating feature branches or pull requests.
- Use a separate branch only while a release is active or when the owner explicitly requests one.

Current state as of 2026-08-25:
- The public product, repository, and workspace name is `Thyme-Me`. Code uses `ThymeMe` for .NET namespaces/projects and lowercase `thymeme` for the executable, solution, database, startup, and single-instance identifiers. `src/ThymeMe.Application/ProductIdentity.cs` governs the public display name and repository URL; restore accepts the pre-rename backup product marker only for backward compatibility.
- The modular implementation is under `src/`, tests are under `tests/`, and CI is in `.github/workflows/ci.yml`. Read `docs/engineering/CODE_MAP.md` before editing and update its ownership mappings when files move.
- Approved stack: C# 14/.NET 10 LTS, WinUI 3/stable Windows App SDK, Generic Host, MVVM, SQLite/EF Core, modular monolith, self-contained x64 portable distribution, and single instance. Release x64 only. Windows 11 x64 is supported without an SLA; Windows 10 22H2 x64 is compatibility-tested only. MSIX tooling remains for development and a future signed installer.
- `docs/product/FIRST_RUN_WIZARD.md` defines the wizard baseline, including a one-action Use recommended defaults path. Basic completion makes optional Advanced setup non-blocking. Google Calendar is deferred and absent from the initial wizard. All choices remain editable.
- Version 1.0.3 uses manual GitHub Release updates and an explicitly inactive update adapter. Current releases expose the unsigned portable ZIP and `LICENSE` beside GitHub-generated source archives. The ZIP root has only `thymeme.exe`, `LICENSE.txt`, `NOTICE.txt`, and `files`; the launcher resolves `files\app\thymeme.exe`, and all other support material remains below `files`. The ZIP SHA-256 is in release notes, GitHub attestations target the ZIP, and SPDX SBOM/third-party notices/provenance/disclosure are bundled inside. Future automatic updates remain behind the adapter/coordinator boundary and require checksum/attestation verification plus active-state deferral.
- Functional behavior is closed for interface-design purposes. All non-Calendar requirements form one initial-release baseline rather than a reduced MVP. Late confirmed decisions include previewed organization migration or replacement, cascading deletion with recoverable retention, scheduled-end crash recovery, signed negative adjustments, Pomodoro cycle-duration pauses that freeze the hard cap, no break application tracking, additive Multiple Categories with drill-down plus non-additive involvement reporting, per-Session currency-minor-unit earnings, raw-time budget counting, versioned ZIP backup with rollback snapshots/remapped merge conflicts, application data excluded from exports unless explicitly selected, packaged CSV documentation, and stable-only prompted updates.
- Thyme-Me first-party code uses the custom Thyme-Me Source-Available License 1.0. Official binaries are free of charge for permitted personal, educational, and internal noncommercial use; redistribution, product incorporation, commercial use, and derivative products require prior written permission. It is not OSI-approved open source.
- Interface phase: follow `docs/product/INTERFACE.md`. The shell uses a non-collapsible icon-only navigation column (64 px default, draggable) and Archive as a primary destination. Home targets about six visible low-alpha color-tinted Stream channels at 1280 px. A persistent Studio One-like bottom transport bar owns global Session selection/configuration and Start/Pause/Stop; channels show their own time and also expose direct Start Timer.
- Transport details: timer left, selectors/mode centered, controls right; visible everywhere except Settings; two-row reflow at 960 px. Every start prompts selected `25`; normal active duration remains editable to move the auto-stop boundary. Channel summary order is Total/Today/This Week with optional vertical budget progress.
- Layout customization: practical horizontal regions and columns are draggable and saved immediately. All Stream channels share one persisted width; dragging any channel edge resizes every channel. Ctrl++/Ctrl+-, Ctrl+0, Ctrl+wheel, and pinch change the persisted whole-interface scale (80–150%) and re-layout the current viewport; Settings can reset the layout.
- Currency entry uses a searchable named-currency picker with CAD and USD pinned first, then remaining currencies alphabetically. Store ISO codes and banker's-rounded currency minor units; never ask ordinary users to enter a raw ISO code.
- History uses one dense header above a virtualized table grouped by sticky date headings, persistent checkboxes, saved non-reorderable column widths, narrow-width priority hiding, and an optional saved-width right inspector. It defaults All time/newest first. Normal Delete confirms; Shift+Delete skips confirmation but still moves the Session to the dedicated recoverable Recently Deleted view.
- Stats: five exact-time headline metrics; fixed-height four-month raw-default daily heatmap with an Effective/Rounded basis option and Daily/Weekly/Cumulative/Timeline modes; selected-day inspector with Sessions and Stream pie; equal fixed lower Time-insight and ranking/breakdown columns that stack narrowly. Show both Top Streams and Top Projects, conditional billing/earnings/raw-time budgets below the headline strip, removable filter chips, and filtered-range Export.
- Timeline: read-only seven-day vertical time grid inside the fixed Stats activity area; month-calendar day picking plus week navigation; active-hour fit with 24-hour toggle; hour-line zoom by buttons, Ctrl+wheel, and touchpad pinch; horizontally scrollable days; fixed day totals/current-time line; low-alpha Stream blocks with origin icons. Split overlaps/cross-midnight/pauses, shade and label stored breaks plus the work-time buffer, dim filtered blocks, and open History for edits. Empty-space selection starts manual entry.
- Archive: tabs are All/Streams/Categories/Projects with Streams as default; persistent search/filters/sort/checkboxes; expandable Stream children; separate Global Category section; saved column/inspector widths; narrow overlay inspector. Projects have zero or one owning Stream, never multiple owners. When a Stream is archived, owned Projects archive automatically; standalone Projects shared through Sessions across Streams are optional unchecked choices with a cross-Stream impact warning. Restore can be bulk for compatible items, defaults parent-archived children selected and independently archived children unselected, and includes an archived owner when required. Active conflicts can queue Archive after Session stops. Permanent organization deletion is one root at a time with cascade preview and typed-name confirmation for large cascades; Session and organization data share configurable-retention Recently Deleted, and organization restores are atomic.
- Settings: responsive card dashboard without an internal sidebar; General first, followed by Appearance, Timing, Pomodoro, Billing, Activity & Privacy, Windows, Data, Updates, About. It has persistent cross-section search, immediate ordinary saves with quiet status, saved Advanced disclosures/detail widths, single-column narrow reflow, and no bottom transport. Updates have separate automatic-check and automatic-download controls. Retention defaults to 30 days with 7/14/30/60/90 and custom 1–365-day choices; a large organization cascade means at least five organization objects or 25 Sessions. Diagnostics exclude paths, tracked activity, descriptions, secrets, and user content. No Google Calendar placeholder ships. Built-in/default UI targets WCAG 2.2 AA principles plus keyboard access, Windows UI Automation, screen readers, text scaling, and non-color cues; acknowledged custom palettes may violate contrast.
